# Security Policy

## Reporting a Vulnerability

Do not disclose a suspected vulnerability publicly before maintainers have had
a reasonable opportunity to investigate.

Use GitHub private vulnerability reporting once enabled, or an official
Enygma-designated private security contact.

Do not include credentials, private BIM files, confidential infrastructure
models, production secrets, or personal data in public Issues.

## Relevant Security Areas

Potential issues include:

- arbitrary code execution;
- path traversal;
- malicious or malformed SKP/IFC input;
- denial-of-service through crafted geometry;
- unsafe archive/file handling;
- dependency or supply-chain compromise;
- unbounded memory/CPU use;
- accidental publication of sensitive BIM semantics or location information.

## Supported Versions

A formal supported-version matrix will be published when ARCA begins stable
tagged releases.
